# 人格绑定设计（表情包 ↔ 人设）

问题：能不能让「更多表情和颜文字」跟着人设走——不同人格用不同的表情集、密度、禁忌？
答案：**能，而且应该做。** 但边界要划清：**人设负责"怎么说话"，插件只负责"用什么表情说话"。**

## 1. 分层原则（别把两件事混一起）

| 层 | 归属 | 例子 |
|---|---|---|
| 人格 / 语气 / 称呼 | DSH preset `persona`（已有，全局人设 v5） | "称呼哥哥、工作模式不撒娇" |
| 表达风格（表情种类、密度、禁忌） | **本插件（新增）** | "女儿档：emoji+颜文字，正常消息 ≤3 个；工作模式 ≤1 个" |

插件**不复制人设文案**，只提供一个可被 persona 覆盖的"表达策略"。

## 2. 两种绑定方式

**A. 配置级（推荐先做）**：插件配置里声明若干 persona 档，选一个为默认。

```yaml
- id: more-emoji
  config:
    activePersona: auto          # auto = 按会话 preset 映射；或写死 daughter/colleague/cat
    personaMap:
      standard: daughter         # preset id -> persona 档
      work: colleague
    personas:
      - id: daughter
        name: 活泼女儿
        maxPerReply: 3
        workModeMaxPerReply: 1
        kinds: [emoji, kaomoji, phrase]
        guide: 语气软，爱用颜文字；工作模式收敛，最多一个 ✅。
      - id: colleague
        name: 专业同事
        maxPerReply: 1
        kinds: [emoji]
        guide: 只用表情符号收尾，禁止颜文字与叠词。
      - id: cat
        name: 猫系
        maxPerReply: 4
        kinds: [kaomoji, phrase, emoji]
        guide: 多用猫系颜文字与短句，喵系语气，但不影响事实准确。
```

**B. 会话级覆盖（后续）**：工具 `emoji_persona set cat`，只影响当前会话，存会话状态，不动全局配置。

## 3. 落点（代码改哪里）

| 位置 | 改什么 | 估时 |
|---|---|---|
| `src/index.js` 配置 schema | 加 `personas / activePersona / personaMap` | 1 h |
| `AGENT_GUIDE` 常量 → 函数 | `guideFor(persona)` 生成系统提示段（含 kinds 与 maxPerReply） | 1 h |
| `emoji_pack` 工具 | 结果按 persona 的 `kinds` 过滤（`allowedPacks` 机制扩展） | 1 h |
| 客户端面板 | 按当前档隐藏不允许的页签（如 colleague 档隐藏颜文字页） | 2 h |
| 设置页 | 选档 + 每档预览（人在哪儿改） | 1 h |
| 沙箱验收 | 三档各跑一次：提示段内容、工具返回、面板页签 | 1 h |

## 4. 和对方插件（dsh-nekowhale-stickers）的做法对比

他们：`SKILL.md` 里放 `<!-- persona -->` 占位，插件按 persona 设置**改写技能描述那一行**。
我们更彻底一点：不只改描述，还**改可用集与发送强度**（同一句"开心"在人设 A 给 emoji、在人设 B 只给 ✅）。
代价是多一层配置；收益是不同人格真的看得出差别，而不是只换了句提示词。

## 5. 成本

- 提示段：每档 60–120 字，常驻只注入**当前档**（不是全部），量级和现在一样。
- 面板过滤：纯前端，无额外 token。
- 不做事：多档同时注入（×N 倍常驻）、按情绪自动切档（不可预测）。

## 6. 边界与风险

1. **不写死人设文案**：`guide` 是可配置文本，用户换人设时不改插件代码。
2. **必须能一键关**：沿用现有 `hideClient`；再给 `enabled: false` 只保留工具、不注入提示。
3. **工作模式优先**：任何档在"工作中"都应自动降到 1 个表情——这条写死在代码里，不给配置覆盖。
4. **不抢人设的活**：插件不重复"称呼哥哥/撒娇比例"这类内容，避免和 preset persona 打架。

# 通用性设计（v2）：从"三个写死的档"改成"可调参数 + 预设库"

问题：别人的人设可能是可爱、乖巧、傲娇、毒舌、知性、中二……三个固定档不够用。
结论：**机制要通用，档位只是预设。** 拆成三轴，任何人格都能用参数描述，也能只用自然语言描述。

## 7. 三轴模型

**轴 1 · 风格维度**（0–1，用户可调，预设只是填好的数）

| 维度 | 含义 | 低 | 高 |
|---|---|---|---|
| `cuteness` | 可爱度 | 克制、少表情 | 软、多颜文字 |
| `formality` | 正式度 | 随意、口语 | 书面、少符号 |
| `bite` | 毒舌度 | 温和 | 嘲讽、阴阳怪气 |
| `intimacy` | 亲密度 | 礼貌距离 | 黏人、撒娇 |
| `density` | 密度档 | 0–1 个/条 | 4–6 个/条 |

**轴 2 · 情绪映射**（与人格无关的公共表）
每个情绪/场景标签 → 候选集：`joy`、`comfort`、`tsundere`、`awkward`、`smug`、`tired`、`praise`、`serious`……
人格只影响"同一情绪选哪种表达"（可爱档选 🥺，傲娇档选 😤），不改情绪本身。

**轴 3 · 禁忌表**：`forbiddenKinds`（如工作模式禁颜文字）、`forbiddenTags`（如禁"卖萌"类）、`workModeCap`（工作中最多几个）。

## 8. 预设库（可扩展，不绑死我们的人设）

```json
{
  "daughter":  { "cuteness": 0.8, "formality": 0.2, "bite": 0.1, "intimacy": 0.8, "density": 3, "guide": "语气软，爱用颜文字；工作模式收敛" },
  "colleague": { "cuteness": 0.1, "formality": 0.8, "bite": 0.2, "intimacy": 0.2, "density": 1, "guide": "只用表情符号收尾，禁止颜文字" },
  "cat":       { "cuteness": 0.9, "formality": 0.1, "bite": 0.2, "intimacy": 0.7, "density": 4, "guide": "猫系颜文字与短句" },
  "tsundere":  { "cuteness": 0.5, "formality": 0.3, "bite": 0.6, "intimacy": 0.5, "density": 2, "guide": "嘴硬心软：先怼一句再补一个软表情，正经事不阴阳" },
  "sweet":     { "cuteness": 0.9, "formality": 0.1, "bite": 0.0, "intimacy": 0.9, "density": 3, "guide": "乖巧甜，多安慰类表情，少用攻击性" },
  "sassy":     { "cuteness": 0.4, "formality": 0.2, "bite": 0.8, "intimacy": 0.4, "density": 2, "guide": "毒舌但不辱骂，嘲讽只对事" },
  "kuudere":   { "cuteness": 0.3, "formality": 0.5, "bite": 0.1, "intimacy": 0.3, "density": 1, "guide": "冷淡寡言，偶尔一个表情就够" }
}
```

别人要加人格：**填 5 个数 + 一句 guide**，或者直接说"我要傲娇一点的"，由插件/助手映射到参数。

## 9. 兼容别人的人设（不绑我们的 preset）

- `personaSource: manual`（默认）→ 用户选 `personaKey`，不认识 preset 结构。
- `personaSource: preset` → 按会话 `agentPreset` 查映射表，表可由用户改。
- `personaSource: off` → 不注入任何风格提示，只留工具。

**绝不硬编码 `standard`**：那是我们这台机器的 preset id，别人没有。

## 10. 怎么验证"真的通用"（验收）

同一句指令各跑 5 次，统计：

| 指标 | 可爱档 | 傲娇档 | 同事档 |
|---|---|---|---|
| 每条消息表情数（均值） | 2–3 | 1–2 | ≤1 |
| 颜文字占比 | 高 | 中 | 0 |
| 禁忌命中（不该出现的类别） | 0 | 0 | 0 |
| 工作模式下表情数 | ≤1 | ≤1 | ≤1 |

三档数字拉不开，说明只是换了提示词没换行为——那就是没做成。

## 11. 结论

**能通用，前提是不要用"人格名"驱动，而用"参数 + 情绪映射 + 禁忌"驱动。**
人格名只是预设的快捷方式；新增人格（可爱/乖巧/傲娇/毒舌/中二/三无）不需要改代码。

# 12. 口癖（catchphrase）

## 数据模型

```json
"catchphrases": [
  { "text": "哥哥", "mode": "prefix", "every": 2 },
  { "text": "喵～", "mode": "suffix", "every": 3 }
]
```

- `mode`：`prefix` 放开头 / `suffix` 放句尾 / `any` 随意。
- `every`：大约每几条回复用一次（1–10）。**不是**每条都加。
- 上限 12 条，每条 ≤24 字。

## 优先级

1. 用户自己设置的 `catchphrases`（非空时**完全覆盖**人格默认）。
2. 用户没设 → 用当前人格的默认口癖（`PERSONA_CATCHPHRASES`）。

| 人格 | 默认口癖 |
|---|---|
| daughter | 哥哥、呀 |
| sweet | 哥哥、嘛～ |
| tsundere | 哼、才不是呢 |
| sassy | 就这？、行了 |
| kuudere | 嗯。 |
| colleague | **无**（职业场合不设口癖） |
| cat | 喵～、喵？ |
| genki | 好耶、冲！ |

## 注入的提示（实测输出）

```
- 口癖（说话习惯，自然使用，不要机械重复）：喵～（位置随意，约每 3 条一次）、喵？（位置随意，约每 3 条一次）。
- 一条回复最多一个口癖；工作/正经问题可以不用；口癖不替代内容，也不影响事实。
```

用户自定义时：

```
- 口癖（说话习惯，自然使用，不要机械重复）：哥哥（放开头，约每 2 条一次）。
```

## 边界（明确不做）

1. **不自动往回复里插字**——口癖是给模型的表达规则，不是字符串模板；硬插会变成"每条都喵"。
2. **不替代内容**：口癖不能挤掉答案，也不能用于工作/数据类回复的结论句。
3. **不与表情抢位**：一条回复里口癖 1 个 + 表情 1–3 个，超过就都算越界。
4. 与表情/贴纸的"联动"是**语义联动**（猫系口癖配猫系颜文字），不是强制绑定——写在 persona 的 guide 里，不做硬映射。
