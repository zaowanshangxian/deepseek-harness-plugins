# 使用说明：工具税

> 面向使用者。装好之后这张卡片在哪、每个数字是什么意思、怎么读、什么时候会慢，都在这。
> 架构与算法细节见 [DESIGN.md](./DESIGN.md)；出问题见 [TROUBLESHOOTING.md](./TROUBLESHOOTING.md)。

## 1. 前置条件

| 项 | 要求 | 不满足会怎样 |
| --- | --- | --- |
| DSH | `>=0.2.1-rc.2 <0.3.0`（实测 `0.2.1-rc.5`） | 页面结构对不上时静默不显示，不报错 |
| `dsh-token-mb` | **建议装**（Token 页由它提供） | 没有 Token 页 → 插件找不到落点，卡片不出现 |
| 会话日志 | `~/.dsh/sessions/**/session*.jsonl.zstd` 存在 | 没有历史会话时「工具账单」为空 |

## 3. 两个数字分别是什么

### 3.1 工具税（副标题里的「≈ N tokens/轮」）

**每轮对话固定要付的 token**：模型每轮请求都要读一遍全部工具的 JSON Schema（名字、描述、参数）。
这个数不随你聊什么变化，是**底盘成本**。

- 来源：`ctx.tools.schemas()` —— DSH 自己投影出的「模型可见工具定义」
- 算法：序列化后的字符数 ÷ 3.5（区间 = ÷4 … ÷3）
- 为什么是估算：本插件没有内置 DeepSeek 分词器，不冒充精确
- 怎么用：工具数越多、描述越长，这个数越大；停用不用的插件能让它直接下降

### 3.2 工具账单（表格）

| 列 | 含义 | 精确度 |
| --- | --- | --- |
| 调用 | `tool/call` 事件次数 | **精确** |
| tokens | 该工具所在轮次（turn/step）的用量，按该轮工具数平摊 | 分摊（归因） |
| 金额 | 同上，按 DeepSeek 峰谷价折算 | 分摊（归因） |
| 占比 | 该工具 tokens / 全部工具 tokens | 相对值 |

**重要**：工具本身没有独立计费。一轮请求可能同时调 3 个工具，账单是**按轮**出的，
所以这里把该轮成本**平均分给该轮每个工具**。

它回答的是「钱花在哪个工具身上」，不是「谁被单独计费」。
拿单个工具的数字去对账会对不上——这是设计如此，不是 bug。

### 3.3 和「花费金额」插件的关系

- 「花费金额」读的是 `dsh-token-mb` 已经算好的**会话级**数字；
- 本插件自己扫会话日志算**工具级**数字，金额用**同一张价格表**（峰谷两档）。
- 两个数不能直接比：本轮 423 次 LLM 调用 vs 452 次工具调用，口径不同；金额差几个百分点属正常。

## 4. 性能（为什么打开不卡）

| 阶段 | 做法 | 实测 |
| --- | --- | --- |
| 首次扫描 | 解压 53 个会话、逐帧解析 | ~2.3 秒 |
| 之后 | 按文件缓存（路径 + mtime + size 命中就跳过） | ~27 毫秒 |
| 重启后 | 缓存落盘 `<DSH_HOME>/tool-tax/cache.json`，启动预热 | 打开即有 |
| 切页 | 客户端 `localStorage` 先渲染上次结果，再异步刷新 | 感知零延迟 |

## 5. 数据存哪

| 位置 | 内容 | 想清掉 |
| --- | --- | --- |
| `~/.dsh/tool-tax/cache.json` | 每个会话的聚合缓存（工具名、次数、token、金额） | 直接删；下次自动重建 |
| `localStorage['tool-tax:last']` | 上一次渲染的数据（用于秒开） | DevTools → Local Storage 删除 |

两者都**不含对话内容**，只有工具名和数字。

## 6. 卸载

1. DSH 里停用或删除插件；
2. 删 `~/.dsh/tool-tax/`（可选）；
3. 卡片随插件一起消失，官方页面恢复原样。
