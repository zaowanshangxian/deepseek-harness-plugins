# 设计 · 工具税

## 问题

DSH 每轮请求都会把「所有可见工具」的 JSON Schema 拼进提示词。装 15 个插件后，这一段的固定成本可能到几千 token——**用户没说话，钱已经在花**。但 DSH 没有把这个数暴露到界面上：token 面板只说「本轮用了多少」，不说「其中多少是工具税」。

## 约束

1. 必须量**模型真正会读到的**那一段，而不是自己重算一份工具清单（DSH 可能有 agent 作用域限制、遮蔽、MCP 动态注册）。
2. token 只能估——没有本地 DeepSeek 分词器。**估算必须标注区间，不能冒充精确。**
3. 归属只能推断：插件注册工具时没有留「我是谁」的元数据。
4. 不接管官方槽位、不改 profile、异常静默——和本仓库其他插件同一条铁律。

## 数据流

```
ctx.tools.schemas()          ← DSH 自己投影出的「模型可见工具」
  └─ normalizeSchemas()      拉平成 [{name, description, parameters}]
      └─ measure()           每条序列化成 {type:'function',function:{...}} → 字符数
          └─ attributeTools()  在 profile/node_modules 的各插件包里找该工具名字面量
              └─ buildReport()   按归属聚合 + 未归属 + Top12 单工具
                  └─ POST /api/tool-tax/report
                      └─ client：官方卡片 <dl> 里追加 <dt>/<dd>
```

## 归属策略（为什么这么土但可靠）

插件运行时没有暴露「这个工具是谁注册的」。三种可选方案：

| 方案 | 可行性 |
| --- | --- |
| 运行时钩 `ctx.tools.register()` 记录调用栈 | 需要 monkey-patch 官方服务，风险高、不干净 |
| 读插件 manifest 里的工具清单 | DSH 没有这个 manifest 字段 |
| **在包里找工具名字面量，唯一命中才归属** | 纯只读、零侵入；`name: 'x'` 和 `const TOOL = 'x'` 两种写法都能覆盖 |

选第三种，并且**多命中/零命中一律记「未归属」**——宁可少归一个，不归错一个。

## token 估算

- 字符 ÷ 3.5；同时给 `÷4 … ÷3` 区间。
- 依据：schema 文本是英文键名 + 中文描述，实测混排落在 3–3.5 字符/token。
- 不引入 tokenizer 依赖（保持零依赖、零安装体积）。

## 与「插件管家」的边界

| 维度 | 插件管家 | 工具税 |
| --- | --- | --- |
| 时间尺度 | 启动（一次性，毫秒） | 每轮（持续，token） |
| 数据 | Loader + 子进程 + Resource Timing + 会话日志 | tools schema + 源码 |
| 改不改 profile | 会（停用/找回） | 不会 |
| 结论 | 该不该停用某个插件 | 停用它每轮能省多少 |

**为什么不含并成一个插件**：数据源、生命周期、风险面都不同（一个要写 profile，一个纯只读）。合并会让「只读」这个卖点消失。

## 已知缺口（留给后续版本，不假装已解决）

1. **系统提示词不在内**：人格、记忆、技能索引的注入走别的通道，本插件拿不到装配后的最终 system prompt。
2. **agentPresets 层扫不到**：`ctx.tools.schemas()` 只覆盖 profile 层 Loader。
3. **归属不覆盖动态工具名**（变量拼接、运行时生成）。
4. **估算误差未用真实 `prompt_tokens` 回标**：需要把 host 半挂到 LLM 请求层，v0.2 再讨论。
