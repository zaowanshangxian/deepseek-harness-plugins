# 四个视频 / 插件 评估（2026-11-11）

> 触发：哥哥给了 4 个 B 站链接，要求「依次分析学习评估改善」。
> 方法：短链 → BV 号 → B 站 view API 取标题/简介/数据；再抓对应 GitHub 仓库 README / Release 说明；结论只写能指回原文的东西。

## 0. 一句话结论

| 项目 | 值得学什么 | 要不要用 |
|---|---|---|
| [DSH-soul 2.1](https://github.com/icyaaaww/dsh-soul) | 图记忆的**作废/取代语义**、产物指纹、原文坐标、图压缩、回放评估 | **学架构，不整体替换**（会和 memhub 双写/双注入冲突） |
| [awesome-gamedev-agent-skills](https://github.com/gamedev-skills/awesome-gamedev-agent-skills) | 77 个游戏技能 + 按引擎路由的 SKILL.md 格式 | **可用**：先试 three.js / Phaser 子集，服务 B 站内容与 demo |
| [dsh-craft-anything](https://github.com/Fanqi89/dsh-craft-anything) | MCP 桥 + 净室/深度双模式 + SHA256 安装校验 | 当前主线用不上，**不装**；要试就单独 profile |
| [dsh-super-agent](https://github.com/TianzeLuo/dsh-super-agent) | Router/Worker、steer 插队、cron 唤醒、审批阻塞可见 + watchdog | **不替换**现有 Agent Teams；吸收 3–4 个点 |

**总判断：维持我们自己的模式（memhub + Agent Teams + HANDOFF），把别人的东西当「选件」拆着用，不做整体迁移。**
理由不是情怀：memhub 已经有迁移好的 140 条、两轮盲审过的治理、体检与检索对比（六套测试 31/27/105/62/22/10）；换栈等于把这些验证全部重做一遍，而收益主要来自 3 个具体机制，不是整套。

## 1. DSH-soul 2.1（BV1R5WH61EHR · 糖霜Official · 1.05 万播放 · 548 赞）

**它是什么**（按官方 README / RELEASE-2.1）：
- 每轮会话结束，规则抽取成「约束 / 决策 / 产物 / 进度」节点，写本地 **SQLite 记忆图**，另建原文片段索引
- 边类型：`derived`（来源）、`supersedes`（取代）、`related`、`coactivated`、`precedes`、`contradicts`（纠正）
- 每轮投影预算 `memory.projectionBytes: 600`（字节，不是 token）；容量 `maxNodes: 500`；维护时合并重复节点
- 可选 `memory.dynamics`（基础激活 / 工作记忆 / 任务线索 / 图上下文 / 侧抑制 / 时间边 / 学习边）；
  可选 `evolution`（成对探测 + 门控 + 影子试用 + 回滚）；独立**图压缩后端**（compaction，就是视频里的「超级压缩」）
- 2.1 重点修的是「误作废」「坐标对齐」「召回排序」「退役可回捞」「产物指纹」「自我污染」，并加回放评估；Schema 9

**值得吸收（按对我们的优先级）**：

| 优先级 | 机制 | 我们现在 | 差距 |
|---|---|---|---|
| **P0** | `supersedes` / `contradicts`：旧结论被新结论**取代**而不是简单归档 | 只有 `archived`（不分「过时」和「被取代」）；检索仍可能把旧结论排前面 | 注入/检索需要「被取代 → 降权/标注」 |
| **P0** | 产物指纹：记录文件 sha256，外部改动后标 stale | orb 只记正文，不校验对应文件是否被改过 | 体检里加一项「stale 产物」 |
| **P0** | 容量策略：**超上限 4 倍才清最旧的非活动记录** | janitor 超上限就淘汰（按权重+最老） | 我们的策略更激进；可改成「先归档，再超 4 倍才清」 |
| P1 | 原文坐标：节点存 `session + seq`，`soul_expand` 按事件展开 | L0 回读只有 id（`memhub_raw`） | 新写入可以带 sessionId/seq；迁移数据补不了 |
| P1 | 图压缩（compaction）独立后端 | 无（只有注入截断） | 不急着做，先看 Soul 的 bench 方法 |
| P2 | dynamics 排序 / 回放评估 | 检索用 IDF + 别名（bench 16/18） | 回放需要真实日志适配，成本高 |

**不学 / 不急**：受控演化（我们有人工确认流程，够用）、SQLite 独立库（我们用 Markdown 真源，可 diff、可手改）。

**风险（必须说）**：
1. 它自己承认「工具块的 JSON `arguments` 还没解码」→ 标准文件工具可能**写了文件但漏记产物**，而产物记忆正是它主打的卖点；回放评分也还没适配真实参数（零分母不能当召回率）。所以视频里的数字别直接采信。
2. 与 memhub **不能同时开**：两套注入会抢预算，且数据源不同（它写 SQLite，我们写 orb）。
3. 它是「插件替宿主做记忆」，我们是「插件 + 可选 CLI + 真源文件」；换它 = 把 140 条 orb 再迁一次，收益要重新验证。

## 2. 游戏技能包（BV1zHnR6uErv · 青青王-AI · 1.53 万播放）

**它是什么**：[awesome-gamedev-agent-skills](https://github.com/gamedev-skills/awesome-gamedev-agent-skills)，**77 个 SKILL.md + 一个 router**，覆盖 12 个引擎（Godot / Unity / Unreal / three.js / Phaser / PixiJS / Bevy / pygame / LÖVE / Defold / Roblox / Ebitengine），号称按 primary docs 写、版本钉死、自带校验脚本。

**能不能用**：能，格式就是 Agent Skills（`SKILL.md` + frontmatter），DSH 的技能库也吃这一套；`npx skills add ...` 能自动识别 agent 装到对应目录。我们的 `indexer.js` 解析 `name/description`，兼容性要真装一次才知道。
**落地（2026-11-11）**：按哥哥要求**全量 77 个**载入隔离库 `L:\DSH\DeepSeek\skills-game`（单独目录，不碰 `~/.dsh/skills`），profile 里 `extraVaults: [{path, label: game}]`；零预注入、按需检索，候选卡标 `[game]`。已验证：索引 77 条 0 error；`searchSkills('three.js 角色控制')` 命中 3 条、`'RPG 存档 系统'` 命中 `rpg`。为解析它的多行 `description: >`，`frontmatter` 增加 YAML 块标量支持。
**对我们的用途**：B 站选题（AI 做游戏）、自己产 demo（three.js/Phaser 门槛最低，能直接进视频）。

## 3. dsh-craft-anything（BV1gf4B6hEo3 · 繁琦啊 · 2.8 万播放）

**它是什么**：把 `craft-anything` CLI 包成 MCP 桥（`mcp__craft__*`），带净室/深度模式切换、状态页、CLI runner、SHA256 校验的安装器。定位是「逆向/重建现成软件」。
**值得学**：① 复杂 CLI 不要塞进工具 schema，用 MCP 桥接（我们 22 个工具已 3375/3400 字符，这条路是对的）；② 净室/深度双模式（默认只允许「从外面看」）；③ 安装器校验 SHA256。
**要不要装**：当前主线（记忆/插件/内容）用不上；真要试，装到单独 profile，别动 desktop。

## 4. dsh-super-agent（TianzeLuo/dsh-super-agent）

**它是什么**：Super-agent 控制面——自然语言入口 + **Router/Worker 双层调度** + 多实例 Web 面板。Worker 复用（Thread 后续投回原 Worker）、中途 `steer` 插队、cron 定时唤醒、目标/里程碑、审批阻塞可见 + watchdog、journal 只追加。
**和我们现在的模式对比**：

| 维度 | 我们（Agent Teams + HANDOFF + memhub） | super-agent |
|---|---|---|
| 调度 | 单会话内 spawn_teammate / team_task / send_message / wait_agent | Router 长驻 + Worker 跨项目、多实例 |
| 长期记忆 | memhub（140 条，分级/治理/体检/检索） | 无（记忆交给别的插件） |
| 交接 | HANDOFF 文件（人可读、可 diff） | 面板 + journal + 会话 |
| 适合 | 单项目深挖、需要「记得住」 | 多项目并行、需要「一直跑」 |

**判断：不替换。** 我们缺的不是「多实例面板」，是「记忆质量」；super-agent 不解决后者。反过来，换过去会丢掉已验证的记忆与交接链路。**可吸收 4 个点**：
1. `steer` 明确「注入下一个模型步、工具调用安全结束后生效」——我们 `send_message` 已是 step 边界，但没写清语义；
2. 审批阻塞可见 + watchdog（我们 approval 关闭，先记着）；
3. 定时唤醒 Router（我们有 `schedule_*`，但没接进团队）；
4. Worker 复用（我们每次 spawn 是新上下文，长期任务会重复读文件）。

## 5. 结论与下一步

1. **维持我们的模式**：memhub 做记忆真源 + 治理/体检/检索；Agent Teams 做执行；HANDOFF 做交接。
2. **吸收 Soul 的 3 个 P0**（下一轮做）：
   - orb 支持 `supersedes` / `contradicts` + 检索降权被取代条目；
   - orb 可选 `sha256` 产物指纹，体检报 stale；
   - 容量策略改成「先归档，超上限 4 倍才清最旧」。
3. **游戏技能**：临时 vault 试 three.js / Phaser 子集，验证兼容与路由。
4. **不装** craft-anything；**不装** super-agent。
5. 视频里的数字（DSH-soul「压缩 43%→83%」等）是它自己的规则摘要基准，不是真实模型收益——引用时保持怀疑。

## 6. 附：子代理「暗面镜子」对哥哥的评价（2026-11-11）

> 由独立子代理 `dark-mirror` 只读生成（读 SELF.md / AGENTS.md / HANDOFF / 归档 / memhub）。原样保留，供哥哥自己判断；我没有替它修饰，也没有替它加码。

**三件可能高估的**
1. **「建了机制＝管住了」**：计划任务 + 自检脚本不少，但 `AGENTS.md` 自己写着 87 个存量目录 0 个有 `EVIDENCE.md`（后来口径改成「不追溯」）；`SELF.md` 两条错断言活了半天；`context/2026-11-11.md` 的「决策与判断」栏还是空模板。机器能核的那半盖住了，人那半空着。
2. **「我在推进主线」**：EP01 从 10-30 卡到今天，卡的是「录 60 秒人声、7 段屏、点发布」——十分钟的动作。同期开了插件、QQ、NapCat、量化、memhub、直播调研，`notes/` 81 个文件。不是懒，是一碰到要露脸的动作就去开新线。
3. **「我给了 AI 自主权」**：账号/收入都给了，但唯一审批人还是你——三份 HANDOFF 里同一条「体检任务要不要换」在等点头。自主被响应速度限流。

**三件可能低估的**
1. **你自己的判据**：「清单不能照单执行」「静默失败看产物」「14B 会编造要复核」都是你核出来的。
2. **你定边界的本事**：「争宠不贬低别人、不造假、不干涉正事」——比多数人对助手的期待清楚。
3. **时间比钱贵**：余额和日预算算到小时级，却没给时间设过预算。

**关系里**：健康的是「标准写在文件里、能查能驳」；风险是「互相等」（我在 HANDOFF 里堆「等哥哥拍板」）和「交付没真看」（面板只验过 API 200，节点没点过）。

**一句不爱听但该听的**：给系统加了那么多约束、给我加了那么多检查器，唯独没给自己一条——**每天完成一个只有你能做的动作**。卡住的事都不是技术问题，是你不在场。
